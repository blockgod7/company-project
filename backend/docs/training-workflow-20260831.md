# 교육 업무 연동 (2026-08-31)

## 처리 범위

- 신규 교육신청서는 신청부서 결재 → 수신자에게 전달 → 수신자가 주관부서 결재선 지정/상신 → 최종 승인 순서로 처리한다.
- `TRAINING_CHANGE`는 독립된 교육 변경·취소 신청서다. 최종 승인 후 원 교육의 유효 일정에 반영한다. 교육 종료일 이후에도 작성할 수 있다.
- 신규 교육훈련보고서는 교육 종료일 다음 날(Asia/Seoul)부터 작성할 수 있다. 작성부서 결재 후 수신자에게 전달되며, 명시적인 접수 완료로 문서와 교육 이수를 완료한다. 수신함 도착/열람은 완료가 아니다.
- 보고서의 저장 이력이 있으면 해당 교육의 변경·취소를 금지한다. 보고서 임시저장도 포함한다. 반려/회수 후 보고서 재작성은 가능하지만 교육 변경은 다시 열리지 않는다.
- 변경·취소 문서가 임시저장 또는 결재 중이면 다른 변경·취소와 보고서 작성을 막는다. 반려/회수/초안 취소 시 이 제한을 해제한다.

## 데이터 보존과 일정

- 교육 연결 식별자는 `formDataJson.fields.sourceTrainingApprovalId`, 변경 기준 버전은 `sourceTrainingRevisionId`다. 서버가 원 신청서 소유자와 최종 승인 여부를 검증한다. 저장한 연결 대상을 바꿀 수 없다.
- 신규 문서에 서버가 `educationWorkflowVersion = "1"`을 기록한다. 연동 도입 전에 저장된 문서에는 표식을 소급 부여하지 않는다. 과거 교육 문서, 결재 내역, 기존 PDF의 일괄 변환은 하지 않는다.
- `/trainings/me`는 현재 인증된 신청자의 문서만 조회한다. 다른 직원 ID를 지정하는 기능은 없다.
- 캘린더 일정은 최종 승인된 원 신청서와 변경·취소 문서로부터 계산한다. 원 신청서의 내용/상태를 수정하지 않고 중복 일정도 생성하지 않는다. 날짜 경과는 `ENDED`, 보고서 접수 완료는 `COMPLETED`다.
- 대시보드 업무 캘린더에 본인의 교육만 표시한다. 구글/아웃룩, 부서 공용 캘린더는 연결하지 않는다.
- 동일 신청자 행을 잠근 뒤 연결 문서 검증/생성을 진행하여 동시 보고서 작성과 변경·취소 경합을 막는다.
- 구매 입고일 수정 API로 교육 문서를 변경할 수 없으며, 이미 생성된 최종 교육 PDF의 교체를 금지한다.

## 적용 및 검증

- `training_workflow_20260831_patch.sql`은 신규 양식 버전과 변경·취소 양식을 등록한다. 기존 결재문서의 템플릿 스냅샷은 변경하지 않는다. 기존 DB에 `(template_code, version)` 유니크 제약이 없어도 반복 실행 가능하다.
- 설정 스크립트는 기존 교육 양식 보정 패치 다음에 새 패치를 실행한다. 기존 보정 패치는 v1만 대상으로 제한한다.
- 서비스 검증: `ApprovalServiceWorkflowTest`, `ApprovalPermissionServiceTest`.
- 실제 PostgreSQL/API/UI 검증: `verify-leave-work.ps1 -TrainingWorkflow -BackupFile <dump> -JavaHome <Java21>`.
- 검증 도구는 별도 PostgreSQL 클러스터와 QA 계정을 사용한다. 원본 업무 DB에 테스트 문서를 생성하지 않는다.

## 확인이 필요한 정책

- 일부 결재자가 이미 결재한 문서에 대한 ‘자동 회수’의 정확한 의미는 추가 확인 중이다. 현재 회수 API는 아무도 결재하지 않은 진행 문서만 회수하도록 기존 규칙을 유지한다. 최종 승인 문서는 회수 대상이 아니다.
