# 휴가계·근무신청서 사용 준비 검증 — 2026-08-31

현재 로컬 프로젝트의 휴가계와 근무신청서가 신청부터 승인·취소·잔액 반영까지 이어지는지 검증한 기록이다. 업무 데이터 삭제·초기화, 새 인사정책 결정, 원격 운영 서버 배포는 이번 작업에 포함하지 않았다.

## 반영한 보완

- 과거 DB의 근무 구분 3종 제한과 20자 길이를 현재 8종·30자와 일치시켰다. 업무 행은 수정하지 않는 재실행 가능한 SQL 패치이며, 기존 직원·근무일별 대체휴무 적립 제한은 유지한다.
- 근무 완료는 한국 시간 기준 종료 시각으로 판단한다. 종료가 시작보다 이르거나 같으면 다음 날 종료로 해석한다. 승인 후 매분 확인하므로 통상 종료 후 1분 이내 완료되고, 조건을 충족하면 대체휴무가 적립된다. 서버 중단 중 지난 일정은 재시작 후 다음 작업에서 처리한다.
- 변경·취소 상신과 자동 완료가 동일 일정을 동시에 변경하지 않도록 원 일정에 쓰기 잠금을 적용했다. 종료된 근무는 변경·취소 상신을 거부한다.
- 같은 직원의 동시 승인에서도 대체휴무가 중복 적립되지 않도록 직원 잠금 후 기존 적립을 확인한다.
- 대체휴무 취소 시 선택한 원 휴가 문서의 배정분만 복원한다. 원문서 식별자가 없는 기존 자료의 호환 처리는 유지한다.
- 휴가계의 만료 안내는 요청대로 12월에만 표시한다. 근무일자 입력에 접근성 이름을 추가했다.

## 유지한 정책

- 특근이 포함된 근무 내역에서 대체휴무를 선택하고 4시간 이상 근무하면 1일 적립한다.
- 서로 다른 신청의 시간을 합산하지 않는다. 같은 직원·근무일에는 기존 DB 정책에 따라 한 번만 적립한다.
- 12월 15일 이후 발생분은 다음 해 1월 31일, 나머지는 해당 연도 12월 31일까지 사용한다.
- 대체휴무 수동 부여는 제공하지 않는다. 휴가관리자의 연차 수량 조정은 유지한다.
- 기존 소수점 적립 및 과거 이력은 보존한다.
- 대리·일괄 신청은 권한이 있는 직원이 같은 부서에 대해서만 할 수 있다.
- E9024의 소속은 사용자 확인에 따라 인사총무(HR_ADMIN)를 유지한다.

## 반복 검증

저장소 루트에서 현재 스키마를 포함한 백업을 지정한다. PostgreSQL 17 도구, Java 21, 설치된 프런트 의존성 및 Playwright가 사용하는 Chrome이 필요하다.

```powershell
.\verify-leave-work.ps1 -BackupFile '<현재 스키마의 백업.dump>' -JavaHome '<Java 21 설치 경로>'
```

- 스크립트는 원 DB에 연결하지 않고 별도 클러스터에 백업을 복원한다. DB 포트는 자동 배정하고 API 8081, UI 5175만 사용한다. 두 포트가 사용 중이면 중단한다.
- 테스트 데이터는 DB 이름이 `groupware_leave_work_qa`인 경우만 입력할 수 있다. 업무 계정 비밀번호를 변경하지 않고 신규 `qa.*` 계정만 만든다.
- 매 실행마다 새 DB를 사용한다. 고정된 2026년 정책·날짜 검증용이므로 다른 연도에 재사용할 때는 테스트 날짜와 연차 fixture를 함께 갱신한다.
- 성공·실패 모두 이번 실행에서 시작한 API·UI·PostgreSQL만 종료한다. 8080/5174 업무 서버는 건드리지 않는다.
- 로그와 격리 DB는 `tmp/leave-work-qa-<실행시각>/`, 화면 증빙은 `frontend/test-results/`에 남긴다. 복제된 업무 데이터가 포함될 수 있으므로 외부 공유나 Git 게시 대상에 넣지 않는다. 임시 암호는 난수이며 보관 설정은 현재 Windows 사용자에게 종속된 암호화 형식이다.
- 테스트 단독 실행은 `E2E_ISOLATED=true` 및 고정된 격리 API 주소가 있어야 한다. 업무 DB 연결 서버에 이 변수를 임의 설정하지 않는다.

이번 성공 실행 기록: `tmp/leave-work-qa-20260831-095856/acceptance.log`, `integrity.log`. 백엔드 전체 테스트 요약: `tmp/leave-work-final-maven.log`. 로컬 서비스 반영 후 DB 검사: `tmp/leave-work-final-db.log`.

현재 업무 DB는 아래 읽기 전용 검사로 별도 확인한다. 자격 증명은 환경변수 등 기존 로컬 설정으로 전달하고 문서에 기록하지 않는다.

```powershell
.\verify-local-db.ps1 -WorkRequestOnly
.\verify-local-db.ps1 -SkipSeedCheck
```

## 사용 순서와 운영 범위

- 전자결재 → 작성 → **휴가, 출장**에서 휴가계·휴가 취소계를, **근무**에서 근무신청서·근무 변경/취소 신청서를 선택한다.
- 신청자는 날짜·내역과 결재/수신자를 확인해 상신한다. 최종 승인된 휴가를 되돌릴 때는 휴가 취소계를 사용한다.
- 근무 변경·취소는 아직 종료되지 않은 승인 일정이 대상이다. 승인된 원문을 직접 덮어쓰지 않는다.
- 연차 수량 조정은 휴가관리자가 사유를 남겨 처리한다. 대체휴무는 승인된 특근의 자동 적립 내역을 기준으로 관리한다.
- 경조 세부 기준·공휴일 등 회사 정책은 기존 등록값을 사용한다. 이를 새 정책으로 확정하거나 2028년 이후 공휴일 외부 연동을 이번 검증으로 대체하지 않는다. 별도 운영 전환 절차는 `leave-policy-go-live.md`를 따른다.
- 기능 검증과 실행 반영 범위는 로컬 프로젝트다. GitHub에는 소스·DB 패치·검증 코드·문서를 게시하며, 원격 운영 서버 배포는 추후 일괄 진행한다. DB 덤프·실행 로그·임시 검증 데이터는 게시하지 않는다.
